## The idea in one paragraph

Every sound the page plays goes through a **lookahead brickwall limiter** running in an `AudioWorklet`. The
limiter holds back about 10 ms of audio, so it sees a loud peak *before* it is played and has already lowered the
gain when that peak reaches the speakers. Nothing leaves the limiter above the ceiling the user chose. Optional
"Even volume" leveling (a compressor) runs before it, and a native compressor after it acts as a last-resort net.

## Components

```
extension/
├── manifest.json            MV3 manifest (Chromium). Firefox's is generated by scripts/build-firefox.mjs
├── js/presets.js            Single source of truth: scenarios, presets, defaults, config migration, host helpers
├── js/limiter-processor.js  AudioWorklet: LookaheadLimiter (pure, unit-tested) + LimiterProcessor wrapper
├── js/content.js            Content script: "Fullscreen-friendly" path, one graph per <audio>/<video>
├── js/offscreen.js          Offscreen document: "Best quality" path, processes the captured tab stream
├── offscreen.html
├── js/background/
│   ├── main.js              Service worker entry: message handlers, shortcuts, tab lifecycle, metering relay
│   ├── storage.js           Config resolution and chrome.storage access (tab / site / global)
│   └── capture.js           tabCapture ownership, rebalancing, badge, pushing config to tabs
├── js/popup/                Popup (ES modules)
│   ├── main.js              Popup class: wires events, coalesces saves, meter loop
│   ├── ui.js                DOM painting, animation (GSAP), sheets, coachmarks
│   ├── config.js            Service-worker round trips
│   ├── format.js            dB formatting and clamping
│   └── theme.js             Theme applied before first paint
├── popup.html / popup.css
├── js/gsap.min.js           Third-party (GSAP), animation only. See THIRD_PARTY_NOTICES.md
├── fonts/                   Outfit + JetBrains Mono (OFL-1.1, see fonts/OFL.txt)
└── _locales/{en,es}/        All user-facing strings
```

`presets.js` is loaded in every context: `importScripts` in the service worker, a `<script>` in the popup and the
offscreen document, the first content script, and plain Node in the tests. It exposes `self.DLPresets`.

The background files are `importScripts`'d into **one shared global scope**. A top-level `const` declared in two of
them kills the service worker at startup, which is why `storage.js` and `capture.js` read `self.DLPresets.*`
instead of destructuring it at the top level.

## Two audio paths

| | Best quality (`audioPath: 'capture'`, default) | Fullscreen-friendly (`audioPath: 'element'`) |
|---|---|---|
| Where it runs | Offscreen document | Content script, inside the page |
| Source | `chrome.tabCapture` stream of the whole tab | `createMediaElementSource()` per `<audio>`/`<video>` |
| Coverage | Everything the tab plays, including Web Audio and MSE/DRM players | Media elements only (open shadow roots included) |
| Player fullscreen | The browser may need F11 (tab capture limitation) | Works normally |
| Browsers | Chromium only | Chromium and Firefox |
| Badge | `HQ` | `ON` |

The path is a user preference, independent of the scenario. Scenarios change only the sound.

The element path cannot be undone: once an element is routed through `MediaElementSource` it stays in the graph.
When its tab gains Best quality, the content script keeps those graphs but sets them **transparent** (limiter
bypassed, leveling neutral) so audio is not limited twice.

## The audio graph

Both paths build the same chain:

```
source → leveling (DynamicsCompressor) → makeup (Gain) → limiter (AudioWorklet) → safety (DynamicsCompressor) → destination
```

- **Leveling** ("Even volume") uses one of `LEVELING_PROFILES` from `presets.js`, or is neutral (threshold 0,
  ratio 1, makeup 1) when off. Music turns it off by default.
- **Limiter**: the lookahead brickwall described below. It reports the post-gain peak and the applied gain back to
  the main thread about every 25 ms.
- **Safety**: `SAFETY_COMPRESSOR` (threshold −3 dB, ratio 20:1, 3 ms attack). A net, not the limiter.

The content script loads the worklet with `audioWorklet.addModule(chrome.runtime.getURL('js/limiter-processor.js'))`
into the page's `AudioContext`, which is why that file is listed in `web_accessible_resources`.

## The lookahead limiter

`LookaheadLimiter` in `extension/js/limiter-processor.js` is pure JavaScript with no Web Audio dependency, so
`tests/limiter-processor.test.js` runs it in Node.

1. Each 128-sample render quantum is **copied** into a pooled slot and queued. The audio thread reuses its input
   buffers, so holding a reference would read new audio later. The pool exists because the audio thread must not
   allocate per block (garbage collection pauses are audible as clicks).
2. Each queued block stores the gain it needs: `min(1, ceiling / peak)`.
3. The gain for the block being emitted is the minimum over **every** block still queued. A loud block four
   quanta ahead already lowers the gain now.
4. **Attack is instant** (drop straight to the required gain), so the ceiling is never exceeded.
   **Release is gradual**, in dB per second from the recovery preset.
5. Gain is ramped linearly across each emitted block, so changes don't click.
6. With `LOOKAHEAD_BLOCKS = 4` the delay is 512 samples, about 10.7 ms at 48 kHz. While the buffer fills at start
   (or after enable/disable resets it) the worklet outputs silence.

The release values are duplicated in `LIMITER_PRESETS` because the worklet scope cannot load `presets.js`. Keep both
in sync.

## Scenarios and recovery presets

From `extension/js/presets.js`:

| Scenario | Ceiling | Recovery | Even volume |
|---|---|---|---|
| Night | −26 dBFS | Slow (`strong`, 4 dB/s) | on, `night` profile |
| Balanced (default) | −20 dBFS | Normal (`normal`, 8 dB/s) | on, `balanced` profile |
| Social | −30 dBFS | Slow (`strong`, 4 dB/s) | on, `social` profile |
| Music | −12 dBFS | Fast (`soft`, 15 dB/s) | off |

Changing the ceiling, recovery or Even volume by hand sets the scenario to `custom`. The stored preset keys
(`soft` / `normal` / `strong`) are older than their UI names (Fast / Normal / Slow); don't rename them, existing
users have them in storage.

`migrateConfig()` normalizes every config that is read or received: it fills defaults, clamps the ceiling to
−60…0 dBFS, maps removed options (`auto` path, `custom` release, `limiterFloor`) to current ones, and derives
`captureEnabled`. Anything coming from storage, messages or an imported file goes through it.

## Configuration and storage

All state lives in `chrome.storage.local`:

| Key | Contents | Lifetime |
|---|---|---|
| `tab_cfg_<tabId>` | The tab's current session config | Removed when the tab closes; orphans pruned on startup |
| `domain_configs` | `{ host: config }` site memory | Until the user forgets the site |
| `global_config` | Config used everywhere when "Apply to all sites" is on | Until turned off |
| `enableCount`, `reviewPrompt` | Local counter for the one-time review prompt | Permanent |
| `seenWhatsNew` | Which onboarding version was shown | Permanent |

The popup theme is in the popup's `localStorage` (`dl_theme`). Nothing is sent anywhere.

`resolveTabConfig()` (in `background/storage.js`) picks the effective config in this order:

1. **Global**: if "Apply to all sites" is on (the tab may still keep its own audio path).
2. **Tab session**: if the tab already has a config. Exception: when site memory says *on* and the session says
   *off*, the site wins, so switching between tabs of the same site doesn't leave one unprotected.
3. **Site memory** for the tab's host (`www.` stripped).
4. **Defaults**.

Without host permissions the service worker often can't read `tab.url`, so the content script sends
`location.hostname` with `pageReady`, and the popup sends the host it sees.

## Best quality ownership (one tab at a time)

The extension runs at most **one** tab capture. `background/capture.js`:

- `rebalanceCaptures()` decides the owner and is **serialized** through a promise chain. Starting or stopping a
  capture flips `tab.audible`, which fires `tabs.onUpdated` and another rebalance; run concurrently, they raced.
- `pickHqOwner()` chooses, in order: the tab the user just acted on (`force`), the current owner if it still wants
  Best quality, the preferred tab, then the best-scoring tab (audible +100, active +50).
- Every other tab that wants Best quality is protected by the element path instead (**soft handoff**). Its badge
  and popup say "Best quality on another tab".
- `tabCapture` needs the extension to have been invoked on the tab (opening the popup or a keyboard shortcut).
  When the service worker tries on its own and fails, the tab falls back to the element path, and the next popup
  open on that tab retries.
- A capture stops when its tab navigates (`status: 'loading'`) or closes.

## Messages

All messages are `{ type, ... }` over `chrome.runtime` / `chrome.tabs` messaging.

| Type | From → to | Purpose |
|---|---|---|
| `pageReady` | content → background | Page loaded; returns the tab's config (host included) |
| `getConfig` | popup/content → background | Effective config + capture state for a tab |
| `setConfig` | popup → background | Save and apply a config (sanitized by `sanitizeIncoming`) |
| `setConfig` | background → content | Push config + `captureActive` to the page |
| `forgetDomain` | popup → background | Remove site memory for a host |
| `importSettings` | popup → background | Merge an imported settings file |
| `getReviewState` / `markReviewSeen` | popup → background | Review prompt bookkeeping |
| `updateDB` | content/offscreen → background → popup | Meter level and gain reduction (relayed at most every 33 ms per tab) |
| `getCurrentDB` | popup → background | Last known level for the tab |
| `start-capture` / `stop-capture` / `update-config` | background → offscreen | Drive the Best quality graph. `start-capture` carries the config because a stream id expires in seconds |
| `startTabCapture` / `stopTabCapture` | test harness → background | Used only by `tests/e2e/hq-manual.spec.mjs` |

Listeners must ignore message types they don't own and **return nothing** for them. Returning `true`, or calling
`sendResponse`, from the wrong listener hijacks the reply meant for someone else (the popup only listens; it never
answers).

## Firefox

`scripts/build-firefox.mjs` generates `dist/firefox/` from `extension/`:

- The background becomes an event page that lists `presets.js`, `storage.js`, `capture.js`, `main.js` in order
  (Chromium uses `importScripts` from `main.js` instead).
- `tabCapture` and `offscreen` are removed, so `HQ_SUPPORTED` is false: every config resolves to the element path,
  and the popup hides the Best quality controls.
- Gecko adds `browser_specific_settings` (add-on id, minimum version 140, no data collection).

**DRM on Gecko**: `createMediaElementSource()` marks an element as captured, and Firefox then rejects
`setMediaKeys()` with `NotSupportedError`, which breaks DRM players (Prime Video, Netflix). On Firefox the content
script only wires an element once it already has MediaKeys, or once it reaches `HAVE_FUTURE_DATA` with no
`encrypted` event on the element or the page. See `#safeToCapture()` in `content.js`.

## Permissions

| Permission | Why |
|---|---|
| `storage` | Saving settings (tab, site and global config) |
| `activeTab` | Lets `tabCapture` capture the current tab after the user opens the popup or uses a shortcut |
| `tabCapture` | Best quality path (Chromium) |
| `offscreen` | A document to run Web Audio on the captured stream (service workers can't) |
| `downloads` | "Export settings" saves a JSON file |
| Content script on `<all_urls>` | The element path has to reach media elements on any site. It only touches `<audio>`/`<video>`, reads `location.hostname`, and may show a short hint in fullscreen |

The extension has no host permissions, makes no network requests and loads no remote code. Adding a permission
changes the install warning for every user and triggers store review, so it needs maintainer approval first.

## Invariants

These must hold after any change. Most are covered by `npm test`.

- Output never exceeds the ceiling, including the first block after start or reset.
- No allocations in the worklet's per-block path.
- `migrateConfig()` accepts any input and returns a valid config with the ceiling in −60…0 dBFS.
- At most one tab capture at a time; rebalances stay serialized.
- A tab is never limited twice (Best quality owner's element graphs are transparent).
- Every user-facing string comes from `_locales`, and every locale has the same keys as `en`.
- Nothing leaves the browser: no network requests, analytics or remote code.
